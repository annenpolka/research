# コンパイル・移行計画・受入条件

**状態：提案・未実装。** 以下のCLI・試験項目は実装済み機能や実行済み結果ではない。

[責務](README.md) / [記法](language.md) / [時間](timing.md) / [イベント](events.md)

## 1. コンパイルの責務

```text
紙 + 固定プリセット + 実験差分
  → CST/AST（位置・コメントを保持）
  → 名前・単位・短縮形・継承・条件を解決
  → KitPlan（ゲーム上の定義）
  → 時間planと必要な観測・操作を解決
  → targetの対応能力と衝突を検査
  → legacy-env / native-bundle
```

KitPlanはbindings、moves/stages、resources、attacks、forms/local-state、cancel/followup/automatic transitions、時間plan、観測要求を持つ。出どころとsource位置は別のmetadata。原作番号や文字列パーサーをrulesへ持ち込まない。

自由なコード実行器ではなく、型付き定義と上限のある実行計画を生成する。条件の同時成立、同一入力の二重消費、即時循環を検査する。ルールの合成順は固定し、行順で決めない。

## 2. targetの能力

能力は項目名だけでなく、対象クラス・演目・variant・借用先・時計・観測精度・利用可能gate・版・検証根拠まで持つ。

| 要求 | legacyでの扱い | 拡張側に必要なもの |
|---|---|---|
| 名前付き弾数/慣性 | 既存意味へ等価に展開できる範囲 | 解決済み定義の読込 |
| 技の再配置 | 既存の有限選択肢だけ | 検証済み演目の任意binding |
| 同じ演目の別技別性能 | 区別不能な値を拒否 | 実行元と設定版の同定 |
| 絶対フレーム窓 | 時計と遷移gateが等価な場合だけ | 正しい実行開始・時計・受付 |
| イベント相対窓 | 予定フレームで代用しない | 実績、位相、必要精度の観測 |
| 共有資源・三段派生 | 同値変換できなければ拒否 | 資源取引、段・入力・中断管理 |
| retime | 実証済みの範囲だけ | source副作用を保つ時間変形 |
| 見た目のみ/判定/生成計画 | その制御能力がなければ拒否 | 独立制御または名前付き実装 |

必要なhookの有効化と、別のゲーム機能の有効化は同じではない。内部依存で無関係な性能まで変わるなら、その依存を含む明示設定を要求する。`ammo` 一行から他武装の弾数を勝手に決めない。

未知・不正・未対応はplayでもrunでも拒否。単なる機能一覧の宣言を実機検証済みの証拠にしない。設置失敗や実行前提の不成立も別に扱う。

## 3. v0で残っている改善候補

基準は `kitc.py` blob `081f05219a9107c942e7423fd7e6c902baac52da`。統合案の整理と文法の英語化では、以下の意味論上の問題は直していない。

- 無効な層への項目がwarningと省略になり、warning表示が `--report` に依存する経路。新契約では標準表示と拒否を分けず保証する。
- `Result.digest()` がenvだけを使い、外部ファイルの内容を含めない。参照先が同じで内容だけ変わる場合を区別できない。
- 出どころ正規表現が `!U<n>` も受理する一方、説明は `!J<n>` を決定としている。決定申告の意味を揃える。
- 語彙と既定値が特定時点の手写し。生成・版固定・互換性検査が必要。

これらを「既に修正済み」とREADMEやテスト結果へ書かない。既存挙動を変えるコード修正は別の変更として試験する。

## 4. 設定の適用と識別

`config_hash` は解決済み実行定義、rules/adapterの版、依存する実データを含む。外部ファイルはパス文字列でなく内容を含める。絶対パス、コメント、表示ラベル、出どころは挙動に影響しない限り除く。完全なハッシュを保存し、短縮表示はUIだけ。

source/evidenceのハッシュは別。意味のある配列順は維持し、辞書のキーだけを正規化する。runではゲーム・DLL・bundleも識別し、設定ハッシュだけで実行環境全体の一致とみなさない。親プロセスの余分な管理対象 `SAIKAI_*` を暗黙に継承しない。

新定義は読込・解決・検証を終えてから一括適用。失敗時は旧設定全体を維持。最初の全面読替えはトレモリセット/ラウンド境界に限定する。

戦闘中更新を後で認めるなら、技・弾は開始/生成時の版に結び付ける。共有資源の容量・予約・リロード進捗には別の移行契約が必要で、版保持だけでは解けない。未定義の移行を許可しない。

## 5. explain / diff / trace

次は将来CLI案で、v0のコマンドではない。

```text
kitc check rena.kit --target <fixed-target>
kitc explain rena.kit --move boomerang --timeline
kitc diff rena.kit --tune slower-sub.tune
kitc build rena.kit --backend legacy-env
kitc build rena.kit --backend native-bundle
kitc verify-install <run-log> --bundle <compiled-bundle>
```

技ごとに、入力、演目、資源共有、発生・硬直・全体、絶対窓/相対窓、条件、継承元、上書き、出どころ、必要能力を表示する。予定と実績、目標時刻と最早観測地点、丸めと副作用を分ける。

traceは実行ID、時計、source位置、観測時刻、受付可否の理由、入力保持/消費、生成/消費の由来を示す。ルートが閉じた理由を調べるために生アドレスを読む必要をなくす。

`verify-install` は設置確認に限る。実動作の一致、衝突や移動の正しさ、保存復元の一致は別試験。ログにない情報を検証済みとしない。

## 6. 段階導入

| 段 | 実装すること | 完了を判断する証拠 |
|---|---|---|
| A：既存入口の信頼性 | 診断、名前付き値、固定既定、ハッシュ、出どころ、explain/diff | v0有効例との等価性、実パーサー照合 |
| B：同定と時計 | Move/StageInstance、開始終了、時計、source観測、絶対窓 | 読取専用traceと既存判断の比較、窓の境界試験 |
| C：発射・命中・接地 | 発射試行/バッチ/実生成、命中取引、接地の意味 | 最後の一発、空撃ち、二本同時発射、古い弾の命中 |
| D：構成可能な行動 | 共通controller、共有資源、有限の段、状態、派生 | 三段射撃等を専用処理なしで組み、中断と競合も正しい |
| E：高度な時間・生成 | retime、見た目独立、移動方針、生成・判定の能力 | 実体と副作用が要求どおり。marker列の一致だけでは不可 |

必要な依存ごとに並行してよい。絶対窓を全イベント完成まで待たせず、当たり調整も由来を保証できる対象から公開する。

保存・復元の型と所有権はBから設計する。全更新入口と復元を実装・検証するまでは、オフラインの検証用機能として扱い、巻き戻し対戦や対応リプレイを使用可能と表示しない。
